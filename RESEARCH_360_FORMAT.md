# Research: DaVinci Resolve "360 File" Format

## The Key Insight
The DJI Reframe plugin for DaVinci Resolve expects input as a **"360 file"** format. This is specific enough that it's likely:
1. A documented format (either DJI proprietary or Resolve standard)
2. Something DJI Studio exports to
3. A container for the metadata we extracted from OSV

## Search Directions

### 1. DaVinci Resolve 360° Support
- Does Resolve have native 360° video handling?
- What formats does it accept? (equirectangular, cubemap, etc.)
- Is there a "360 file" specification in Resolve docs?

### 2. DJI Ecosystem
- Does DJI SDK mention "360 file" format?
- What does DJI Studio export when you choose "DaVinci Resolve"?
- Any DJI developer documentation on the format?

### 3. Possible Format Types
Could be:
- **Equirectangular MP4**: Single 360° projection (e.g., 4096×2048)
- **Cubemap format**: 6 or 8 face images (likely for Osmo 360)
- **Metadata wrapper**: OSV + sidecar XML/JSON
- **Custom DJI format**: Proprietary container

### 4. File Extensions to Search
- `.360` or similar
- `.dji360`
- `.equirectangular`
- `.cubemap`
- Any custom extension

## Likely Scenarios

### Scenario A: "360 File" is a Video Format
- Osmo 360 outputs 8 camera views
- "360 file" = stitched equirectangular MP4
- DJI Studio stitches the 8 views → single 360° video
- Resolve can display/manipulate 360° content
- **Implication**: We may need to implement stitching

### Scenario B: "360 File" is a Metadata Container
- "360 file" = OSV file itself or wrapper around it
- Contains video + embedded calibration data
- Resolve can read and interpret the metadata
- **Implication**: Might already work if we just rename/wrap the OSV

### Scenario C: "360 File" is a Proprietary DJI Format
- Specific binary or XML format designed by DJI
- Only generated by DJI software (DJI Studio, DJI Reframe)
- We need to reverse-engineer or find spec
- **Implication**: More work to implement converter

### Scenario D: "360 File" is an Industry Standard
- Could be MPEG-I 360° format
- Could be Spatial Media format (used by YouTube, Facebook)
- Could be Khronos glTF or OpenEXR with 360 metadata
- **Implication**: Existing libraries might help
